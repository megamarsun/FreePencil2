## パラメータスイープの知見(2026-07-15、5モデル×10設定、out/sweep/)

対象: 車(audi_r8)/人物(woman_01)/メカ(kaino-mech)/有機物(squid)/機械小物(eiffel※実体は電話)
設定: sharp 15/30/45/60/85°、quads±、色距離 0.3/0.5/0.8、sharp_clear

1. **sharp_edges が支配的、最適値はモデル系統で別**。有機系は 15〜30° で
   四角ノイズが大量発生(人物の膝・胸)、85° が最良。ハードサーフェスは
   15〜85° で見た目ほぼ不変(構造溝は90°近いため)。**汎用デフォルトは 60° 前後が安全**
2. **微小島の爆発が最大のムダ**(最重要改良ターゲット)。Audi 15°で 92,553 島 →
   85° で 4,931 島だが見た目ほぼ同じ = 微小島は線に寄与せず、色制約違反・
   断片化・処理時間だけを生む。→ **STEP1 に「小島マージ」**(面数/面積が閾値未満の
   島を隣接最大島に併合)を入れると、角度しきい値への感度が消えて全系統で安定するはず
3. **色距離はライン抽出には 0.3 で十分**(dist03 と dist08 の線画は目視同一)。
   0.8 は違反爆発(6,685/80,382 on Audi)する実現不能領域。違反削減より
   「隣接グラフ彩色+固定パレット」で構造的に距離保証する方が本筋
4. **to_quads は線画に効果ゼロでSTEP1が1.4〜1.6倍遅くなる**(5モデル全てで色数・ink同一)
5. **fp_sharp_clear は全モデルで完全無効果**(インポートアセットはシャープマーク無し)

## 車/人間/ロボット 3種スイープの考察TDD(2026-07-16)

### 最重要発見: PROノードの線抽出は「輝度差」で決まる(RGB距離ではない)

- ノード内部: mecha/bone を **Alphaで白背景にプリミックス → Filter(エッジ検出)
  → ColorRamp(float入力=輝度)**。ランプは 0.2〜0.38 で黒飽和。
- つまり: 内部線の濃さ = 隣接島の**輝度差**、シルエット線の濃さ = **1−輝度**(白との差)。
  RGB距離を最大化しても輝度が近いと線は消える(womanの顔・服の線が消えた回帰の真因)。
  スイープで dist03/dist08 の見た目が同一だった謎の答えでもある。
- 対応: パレットを**輝度ラダー方式**に再設計(utils.build_palette v3)。
  輝度[0.25,0.75]を等間隔配置(上限0.75=シルエット保証)、連続クラスほど輝度が
  離れる交互割当、各スロット内でRGB距離を最大化(multi-restart 12色相)。
  回帰テスト: t13(隣接島の輝度差>=0.12・全色輝度<=0.85)。
- **残課題**: クラス数kが大きいと輝度間隔 0.5/(k-1) が縮み、一部の内部線がグレー化。
  旧乱数色との比較画像: out/sweep4/compare_woman_final.png。根本解は
  (a)ハイブリッド: 島ごと乱数色相+クラス輝度レベル(見た目の豊かさ復活、RGB契約は緩む)
  (b)ノード側にランプ感度パラメータ(小さい輝度差でも黒に飽和させる)のどちらか。

## (経緯記録)ボーン塗り分けの実験(2026-07-16、差し戻し済み)

- 旧実装は「線になる塗り分け」になっていなかった:
  (1) ウェイト加重平均で色を混合 → スキンウェイトが滑らかなので境界がグラデーション
      になり、エッジ検出に掛からない(線が出ない)
  (2) ボーン色がハッシュで [0.16,0.61] の狭い暗域 → 隣接ボーン間の輝度差が出ない
- 新実装(vertex_color.py ボーン節):
  **支配ボーン(最大ウェイト)による離散塗り分け** + **ボーン隣接グラフ彩色**
  (エッジ両端の支配ボーンが異なれば隣接)+ **輝度ラダーパレット**(mecha側と同一機構)。
  fp_bone_grouping_mode(exact/basename/stripdigits)は従来通り効く。
- 結果: woman で首・肩・胸・腰・膝・足首にボーン境界線が出るようになった
  (out/sweep4/renders/069_woman...auto_bone_white.png)。
- 残改善: 境界線がウェイト解像度なりに波打つ(スムージング候補)、
  線の濃さはノード側ランプ感度パラメータでさらに改善可能。
- テスト: tests_assets t_human は「離散色数 2〜64」(旧混合は数百の中間色を生むため
  離散性そのものが正しさのシグナル)+輝度上限を検査。

## PROノード本体の改良(2026-07-16、Exported_FreePencil_v1_1_0_pro.py を直接更新)

### 解読したノード構造(重要知識)

- 5チャンネル(mecha/depth/bone/gen/mat)それぞれ:
  「白背景プリミックス → Sobel → RGB平均 → ColorRamp(CONSTANT)」で色付き線化し、
  全チャンネルを MULTIPLY 合成。
- 最終段: 合成線画像の RGB平均 → n_39 ramp(EASE, 0..0.827) → 反転 = **線のアルファ**。
  線の色は line_color 入力(既定黒)で一律描画。
- **チャンネル色は出力に色として現れず、「RGB平均が高いほど線が薄くなる」不透明度**:
  旧: mecha黒=100%、bone赤/depth緑/gen青=65%、matマゼンタ=33%。
  → ボーン線・シルエット(depth)線がグレーだった構造的原因。
- 薄緑背景の正体は n_53 AlphaOver のベース色 (0.5,1,0.5) だった。

## 骨格モデルの潰れ修正(2026-07-16、ユーザー指摘)

  黒潰れ消失。単体ボール(1パーツ)は従来どおり分割線が出る(t11/t15で両方向を固定)。

## 硬境界ボーン fp_bone_hard_names(2026-07-17、顎下ライン)

- 「顔と首でボーン色が違うのに線が出ない」理由: ボーン塗りはウェイト加重平均で、
  境界の色が**なだらかな階調**になるため、エッジ検出(急峻な変化に反応)に
  掛からない。「色が違う」だけでは不十分で「急に変わる」必要がある。
  さらにハッシュ色は偶然近いこともある。
- 対策: `fp_bone_hard_names`(カンマ区切りボーン名、既定空=挙動不変)。
  列挙ボーンのウェイトが乗る頂点はブレンドせず**支配ボーンの純色**で塗る
  → 支配の切り替わり(head/neck)がステップになり線が出る。
  woman + "head,neck" で顎下〜耳へのジョーライン出現を確認
  (out/chin_test/compare_chin.png)。プリセットキー "bone_hard_names"、
  プリセット auto_chin あり。回帰テスト t17(17+3 全PASS)。
- 含意: 線の出るボーン境界はアーティストが選ぶ設計(全境界硬化はリング地獄、実証済み)。
  ウェイトの塗りを急峻にすれば同じ効果を手動でも作れる(線=ウェイト設計の反映)。

## パーツ・トーン分け fp_part_tint(2026-07-17、生え際・襟ライン)

- 「顔と髪も線が出るはず」の答え: 髪も顔もどちらも head ボーン支配なので
  bone_color が**まったく同じ色**になり、接していても境界に色差ゼロ=線ゼロ。
  mecha 側も別オブジェクト同士はメッシュ辺を共有せず隣接扱いにならないため
  輝度が偶然近いと線が出ない。
- **アーキテクチャ確定(ユーザー判断)**: ボーン付きモデルでは
  「mecha の塗り分け≒パーツ単位」。つまり **mecha_color がパーツ境界線を担い、
  bone_color は元の純粋なウェイトブレンドのまま、PROノードで両チャンネルを
  合成(乗算)する**のが正しい分担。bone_color には一切手を入れない。
- 実装: `fp_part_tint`(既定ON)。選択オブジェクトの bbox 近接グラフを彩色
  (color_graph_greedy の再利用)し、接するパーツ同士が必ず違うクラスになる
  ようにして、**mecha パレット全体**にパーツごとの明度オフセット
  (0 / +0.17 / +0.34、上限0.85クランプ)を加算。パーツ内の島彩色は無傷で、
  パーツ境界だけに輝度ステップ=線が出る。単一オブジェクトでは無効果。
- 検証: woman で襟・袖口・顎まわりの線が出現
  (out/part_tint/compare_head_mecha.png)。fredy は口元改善、loli は首/襟の
  境界出現、劣化なし(compare_others_mecha.png)。プリセットキー "part_tint"、
  比較用プリセット auto_bone_notint。回帰テスト t18 は mecha の輝度差
  (ON≥0.12 / OFF<0.05)と bone_color 純粋性(ON/OFF完全一致)を保証。
  18+3 全PASS。

## チャンネル別線強度スライダー(2026-07-18、B案=パネル駆動)

- ブランチ `feature/line-channel-sliders`(コミット a955916=セッション作業一式、
  6f02f18=本機能)。dev/batch は .gitignore 対象なのでテストは未追跡のまま。
- `fp_core.apply_line_tuning(group, sensitivity, strengths)`:
  position = 元位置 × 全体感度 ÷ チャンネル強さ。強さ2.0=しきい値半分、
  0=チャンネルOFF(位置1.0)。元位置は fp_orig_positions に保存で冪等。
  チャンネル→ランプ対応はノード名固定(mecha=ColorRamp, depth=.001,
  bone=.002, gen=.003, mat=.006)。apply_line_sensitivity は互換ラッパー。

## 白マテリアル強制プレビュー(2026-07-18、fp_white_preview)

**最終形(51de190、ユーザー意図)= コンポジタ切替方式**: PROノードは
「入力Imageの上に線を描く」ので、グループの Image 入力の手前に
MixRGB(ビューティ⇔白、ラベル FP_WhitePreviewMix)を挿入し係数1つで切替。

  プロパティ fp_orig_mats に保存(=ONのまま保存しても後で復元可能)。
  スロット構造維持・二重ONでバックアップ非上書き・スロット無しは白追加→除去。
- **EEVEE Next は view_layer.material_override を無視する(2026-07-18実測)**。
  そのためオーバーライドではなくスワップ方式。リンク/オーバーライド
  オブジェクトはスキップ。テスト t23(23+3 PASS)。
  コミット 407eb30(feature/line-channel-sliders ブランチ)。

## 深度チャンネルの相対勾配化(2026-07-23、1dcd586)

- ユーザー指摘「深度の正規化ができてない、弱すぎ」は正確だった。
  旧構造 = Depth → **Normalize(フレームmin-max)** → Sobel。背景の Z
  (遠クリップ、数百m〜)が正規化の分母を支配し、シーン内部の深度段差
  (0.5m 等)は 0.001 以下に潰れて線にならない=深度は実質
  「対背景シルエット専用」だった。
- 新構造 = **Sobel(生Z) ÷ (Z + 0.5)、clamp** の相対深度勾配。
  「深度が何%変化したか」なのでシーンスケール・背景・カメラ距離の
  絶対値に依存しない。深度10%の段差が既定しきい値(0.15)を確実に
  超え、グレージング角の床は誤検出しない(ARIAの部屋で確認、
  compare_depthv2.png / matline_depthv2_*.png)。
- 既存 blend への反映はノードグループ削除→STEP3 再生成が必要
  (depth_verify.py 参照)。深度スライダーが実効的に効くようになった
  (2.0でしきい値半分=深度5%の段差まで拾う)。
